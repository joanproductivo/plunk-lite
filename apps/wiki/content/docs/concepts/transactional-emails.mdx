Transactional emails are emails sent directly through the API. They are typically used for one-to-one communication, such as password resets, order confirmations, and notifications.

## Sending with attachments
Plunk supports sending attachments with transactional emails. By default, you can include up to 10 attachments per email with a maximum total size of 10MB. Attachments should be base64 encoded and included in the `attachments` array when sending the email via the [/v1/send](/api-reference/public-api/sendEmail) endpoint.

A `/v1/send` request can be at most 10 MB, so attachments, which travel base64-encoded, can add up to about 7 MB. Self-hosters can adjust the defaults — see [Environment variables](/self-hosting/environment-variables).

## Sending from a template
You can also send transactional emails using a [template](/concepts/templates) you have created in the dashboard. This allows you to reuse the same design and content for multiple emails, while still personalizing them with contact data.

## Adding recipients to segments
Pass `segments`, a list of up to 20 entries with static segment ids, and every recipient an email is created for joins them in the same call — for example, the people a signup form sends a welcome email to. `null`, an empty string, and blank or `null` entries (`[""]`) name none. The ids are checked before anything is sent, so one that is not a static segment of the project answers `422`, naming its place in the list. A recipient whose email is refused is not added. Adding a current member counts as a new entry, which fires the segment's `entry` event again when it tracks membership. See [Segments](/concepts/segments).

## Opt-out topics (Plunk Lite)
A transactional template can have an **opt-out topic**: a static segment, chosen in the template's settings (or with `optOutSegmentId`). Use it for notices that go to many people, never for receipts or access emails. Its emails then carry a one-click unsubscribe header (`List-Unsubscribe`, RFC 8058) and the notices footer, set by language in **Settings → Brand**, which lead to the opt-out page. A contact who opts out joins that segment and stops getting the templates of that topic, from workflows and from `/v1/send`; every other transactional email still reaches them.

`/v1/send` with such a template to a contact who opted out answers `422` `CONTACT_OPTED_OUT` for that recipient and sends nothing to them, even if the request passes its own `body`. The contact is still created or updated, and `subscribed: true` still applies, but it does not join the call's `segments`. A workflow step completes, with an email marked failed: "Contact opted out of this kind of email". See [Unsubscribe pages](/guides/unsubscribe-pages#opt-out-topics-plunk-lite).
